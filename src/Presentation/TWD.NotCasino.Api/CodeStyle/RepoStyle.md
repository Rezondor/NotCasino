# Стиль оформления репозиториев для ORM в C# проектах

## Общие положения
Репозиторий отвечает за взаимодействие с базой данных через ORM (например, EF Core).  
Все методы должны быть асинхронными и возвращать `Task` или `Task<T>`.  
Работа с сущностями должна учитывать контекст использования: чтение, обновление, добавление или удаление.  

---

## Получение данных

### Правила
Для функций получения объектов из БД должно быть реализовано **два вида получения**:

1. **Для обновления (`Get...ForUpdateAsync`)**  
   Возвращает сущность с отслеживанием (`AsTracking`).  
   Используется в случаях, когда планируется изменять данные и сохранять их через `SaveChangesAsync`.

2. **Без отслеживания (`Get...Async`)**  
   Возвращает сущность без отслеживания (`AsNoTracking`).  
   Используется для операций, где требуется только чтение данных.  

> Исключение: если необходимо получить только часть данных (например, 2 поля из 6), то использование `AsNoTracking` является стандартом и реализуется через проекции (например, `Select`).

### Примеры
- `GetByIdAsync(Guid id)` – получение сущности для чтения.  
- `GetByIdForUpdateAsync(Guid id)` – получение сущности для обновления.  
- `GetAllAsync()` – получение набора сущностей без отслеживания.  
- `GetFilteredAsync(...)` – выборка по условию.  

---

## Обновление данных

### Правила
Для обновления сущностей существует два подхода:

1. **Прямое обновление без получения**  
   Используется, если логика компонента допускает обновление конкретных полей напрямую.  
   Реализуется через `Update...Async`, где EF Core выполняет обновление по ключу без загрузки сущности.

2. **Обновление через отслеживание**  
   Если необходимо получить объект, изменить его свойства и сохранить изменения, то используется:
   - Получение сущности через `Get...ForUpdateAsync`
   - Изменение её полей
   - Вызов `SaveChangesAsync`  

### Требования
- Методы обновления должны возвращать `bool`, отражающий успешность операции.  

### Пример
```csharp
public async Task<bool> UpdateNameAsync(Guid id, string newName)
{
    var entity = await _dbContext.Entities.FirstOrDefaultAsync(e => e.Id == id);
    if (entity == null) return false;

    entity.Name = newName;
    await _dbContext.SaveChangesAsync();
    return true;
}
```

## Добавление данных

### Правила
- Добавление объектов производится через стандартные методы EF Core:  
  - `AddAsync` – для одного объекта  
  - `AddRangeAsync` – для коллекции объектов  
- Входящим параметром является полностью собранный объект сущности БД.  
- Функции должны быть асинхронными и возвращать `Task`.  

### Пример
```csharp
public async Task AddAsync(Entity entity)
{
    await _dbContext.Entities.AddAsync(entity);
}
```

---

## Удаление данных

### Правила
Удаление объектов должно быть **мягким (soft delete)**.  
Для этого в сущности необходимо добавить поле:

```csharp
public DateTime? DeleteDate { get; set; } = null;
```

- При удалении объект помечается временем удаления (`DateTime.UtcNow`).  
- Реальных удалений из БД быть не должно, чтобы сохранить целостность данных.  

### Пример
```csharp
public async Task<bool> DeleteAsync(Guid id)
{
    var entity = await _dbContext.Entities.FirstOrDefaultAsync(e => e.Id == id);
    if (entity == null) return false;

    entity.DeleteDate = DateTime.UtcNow;
    await _dbContext.SaveChangesAsync();
    return true;
}
```

---

## Итоговые правила

1. **Все методы асинхронные.**  
2. **Два варианта получения данных:**  
   - С отслеживанием (`ForUpdate`)  
   - Без отслеживания (`NoTracking`)  
3. **Обновление:**  
   - Прямое обновление при необходимости  
   - Через отслеживание и `SaveChanges` в остальных случаях  
   - Всегда возвращать `bool`  
4. **Добавление:** только через `AddAsync` / `AddRangeAsync`  
5. **Удаление:** только soft delete (`DeleteDate`)
